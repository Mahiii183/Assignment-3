(1) Both the filters count the number of pixels whose red value is greater than both the green and blue values. The difference is actually their loop order so the filter1 traverses the image column by column while filter2 traverses it row by row and since the pixel array is stored in row-major order, filter2 accesses consecutive memory locations and benefits from better spatial locality whereas filter1 jumps between rows and may experience more cache misses.

(2) The plot shows that the execution time increases with image size and filter2 is generally faster than filter1, especially for the larger images. For the 4096 × 4096 image filter1 averaged 0.131564 seconds compared with 0.074845 seconds for filter2 which makes filter2 approximately 1.76 times faster. The raw timing data varies between runs so for the largest image, filter1 ranged from 0.128485 to 0.137907 seconds (a difference of 0.009422 seconds), while filter2 ranged from 0.063501 to 0.113655 seconds (a difference of 0.050154 seconds). Although filter2 was faster overall its results showed greater variability for the largest image and filter1 was slightly faster at 512 × 512.

(3) the cachegrind shows that the filter1 experienced 1,346,273 L1 data cache misses (2.2% miss rate), while the filter2 experienced only 394,717 misses (0.7% miss rate). Filter1 accesses the pixels column by column jumping between rows in the row-major pixel array, whereas filter2 accesses adjacent pixels sequentially and benefits from better spatial locality. This reduces the filter2's L1 cache misses and helps explain why it ran faster in the timing experiments. So both filters had the same last-level data cache misses (198,111), indicating that the main observed cache difference was at the L1 level.
